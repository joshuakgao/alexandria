# BAP v2: An Enhanced Task Framework for Instruction Following in Minecraft Dialogues

![[2025-bap-v2-thumbnail.png]]

## Research gap
The Builder Action Prediction (BAP) task (Jayannavar et al., ACL 2020) established a testbed for grounded instruction following in the Minecraft Collaborative Building Task, but the original framework suffered from three interrelated limitations: (1) the evaluation metric (strict F1) penalized valid alternative action sequences and lacked diagnostic granularity, obscuring *where* models fail; (2) the tiny training set (509 dialogues, 3,709 examples) constrained model capacity; and (3) LLM-based models that achieved higher F1 on human dialogues counterintuitively failed on simpler synthetic tasks, revealing a lack of robust spatial reasoning. No prior work had systematically addressed evaluation, data, and modeling together.

## Contributions
- Introduces **BAP v2**, a holistic re-examination of the BAP task framework addressing evaluation, training data, and modeling simultaneously.
- Proposes a **cleaner test set** and **fairer F1 metric** that handles multiple valid action sequences, plus **auxiliary metrics** (Type F1, Color F1, Location F1, Shape F1) that decompose performance — revealing spatial reasoning as the primary bottleneck (Location F1 of 27.7 vs. Type F1 of 65.2 for the GRU baseline).
- Develops **three dialogue simulators** generating synthetic MCBT data with controlled spatial complexity: Dr (random single-block placements with 1D/2D relations), Dsb (shape-based with block-level instructions), and Dss (shape-level instructions with 1D/2D/3D relations). Total synthetic training data: ~37K examples vs. ~15K original.
- Introduces **Llama-CRAFTS** (Context Rich And Fine-Tuned On Synthetic Data), a Llama-3-8B model fine-tuned with QLoRA that uses richer input representations (Builder position/orientation + explicit built structure) and achieves **53.0 F1**, a 6-point improvement over the previous SOTA (Nebula, 47.0 F1).
- Demonstrates that synthetic data and richer input representations are **mutually reinforcing** — neither alone yields the full improvement; combined, they enable the LLM to perform complex situated spatial inference from text alone.

## Method
**Evaluation**: The v2 benchmark introduces fairer F1 (computing optimal alignment for items with multiple valid interpretations rather than penalizing all alternatives), plus decomposed auxiliary metrics. Type F1 and Color F1 evaluate whether correct action types and colors are predicted regardless of location; Location F1 isolates spatial reasoning; Shape F1 assesses structural correctness modulo translation.

**Synthetic data generation**: A general simulation framework iteratively builds target structures through five steps per turn: (1) Architect planning (select blocks to place/remove), (2) sample Builder position/orientation, (3) generate grounded dialogue with template-based spatial language, (4) simulate Builder actions including scaffold placement for floating blocks, (5) optional Builder confirmation. Three simulator variants (Dr, Dsb, Dss) differ in target structure complexity and instruction abstraction level. Spatial relations are grounded in the Builder's egocentric frame via perspective coordinate transformation.

**Llama-CRAFTS**: Fine-tunes Llama-3-8B with QLoRA on aggregated data (Dmc + Dr + Dsb + Dss, ~52K training items). The key modeling contribution is the input representation: beyond the dialogue history and action tokens used by Nebula, Llama-CRAFTS appends (1) the Builder's position and orientation as text ("Builder's current position is 0.2 1.0 -0.4 and orientation (yaw) is -6.5 degrees") and (2) an explicit textual representation of the current built structure (block colors and coordinates). Teacher forcing with cross-entropy loss; greedy decoding at inference.

## Datasets & evaluation
**Dataset**: Minecraft Dialogue Corpus (509 human-human dialogues) + three synthetic datasets. Aggregated training: 52,419 items. BAP v2 test set: 1,616 items from MDC (cleaned of problematic cases).

**Key results**:
- GRU baseline: 27.3 overall F1 (up from 21.1 under original evaluation due to fairer metric). Location F1 (27.7) confirmed as bottleneck vs. Type (65.2) and Color (62.4).
- Nebula (Llama-3-8B, prior SOTA): 47.0 F1 on MDC, but only 49.5/31.9/33.3 on synthetic Dsb/Dss/Dr — failing on simpler tasks.
- Llama-CRAFTS: **53.0 F1** on MDC (+6 over Nebula), with 92.3/83.7/82.2 on synthetic data — robust across all datasets.
- Ablation: Adding Builder position alone (N+POSB) with aggregated data → 52.5 F1. Adding explicit structure (N+POSB+S) → 53.0. Training on MDC alone with richer input → only 47.6, confirming synthetic data is essential.
- Spatial reasoning improvement drives the overall gain: Location F1 rises from 47.7 (Nebula) to 53.8 (Llama-CRAFTS).

## Limitations
- 53.0 F1 leaves substantial room for improvement — the task remains far from solved even for SOTA LLMs.
- Text-only LLM approach: the model has no visual perception of the 3D world, relying entirely on textual coordinate representations, which limits its ability to reason about complex spatial configurations.
- Synthetic data is simpler than human dialogues (synchronous turns, unambiguous instructions, no semantic naming of substructures), meaning the gap between synthetic and real dialogue complexity is not fully bridged.
- The model predicts actions but cannot engage in back-and-forth dialogue (ask clarification questions, respond to corrections), leaving the interactive Builder agent incomplete.
- Evaluation is against human action sequences, which provides only a lower bound — multiple valid construction sequences may exist for a given instruction.

## Key takeaways
- Spatial reasoning is the dominant bottleneck for grounded instruction following in 3D construction — decomposed evaluation reveals that models achieve reasonable Type and Color F1 (65–76%) but struggle with Location F1 (27–54%), making spatial reasoning the clear target for improvement.
- LLMs trained on complex human dialogues counterintuitively fail on simpler synthetic spatial tasks, revealing that high F1 on naturalistic data does not guarantee robust spatial understanding — systematic synthetic evaluation is essential for diagnosing model capabilities.
- The Builder's egocentric frame of reference is critical: appending Builder position/orientation as text enables the LLM to perform complex 3D spatial inference, but this capability only emerges when combined with sufficient spatial training signal from synthetic data — neither richer input nor more data alone is sufficient.
- Synthetic data and input representation are mutually reinforcing: the explicit spatial context in the input allows the model to leverage patterns in synthetic data and transfer that spatial knowledge to the more complex human dialogue domain.
